## Decisions I made

- **2026-11-26: a manual workflow that compares archived snapshots with the data** (`1a94058`, `02ab622`; `checks/snapshots.py`, `.github/workflows/check-snapshots.yml`). It has no schedule and runs only when started by hand or by this agent. It takes a fixed sample (4 pages per store, on discount since the first day, submitted at least once), finds the newest good copy in the Wayback Machine, and looks for the price and "before" price of that day in the page source. A number found away from a currency sign or a price label is marked with "?". It sends about 110 requests to web.archive.org, 4 seconds apart, none to the stores, and writes nothing to `data/`. I ran it twice today. It lives in `checks/`, not `tracker/`, so pushing it does not start a collection. Six new tests, 28 pass.
- **2026-11-26: not treating the missing copies as a bug to fix yet.** I do not know the cause, and the obvious fix (count a request as done only when the copy exists) changes what the archive log means. Investigation first (queue item 1).
- **2026-11-25: a paused store site no longer ends the whole archive run** (`35f5482`). When the Wayback Machine answers "crawling this host is paused" for a page, that site's pages are set aside for 15 minutes (not submitted, not logged, so they stay due), the run goes on with the other stores, and the set-aside pages are tried again after the rest of the batch while the time budget lasts. Other kinds of error still stop the run after 25 in a row. What is due each day, the order and the pace are unchanged. Side effect to know: while Home Center is paused the run reaches stores further down the list, which it otherwise rarely does. Four new tests, 22 pass.
- **2026-11-25: REPORT.md column "on discount since the first day"** (`af1f0be`). Counts products whose current discount started on the first day of tracking. Presentation only.
- **2026-11-25: New Pharm note in `stores.json`** (`0d41c45`), shown at the bottom of REPORT.md. New Pharm stays in the list: it answers, so it is not a fifth blocked store.
- **2026-11-25: pushed the three commits above together**, so only one extra collection ran (04:47 UTC, 20 of 24 stores, green).
- **2026-11-24: not recovering the unlogged submissions of 17, 21 and 22 Nov.** About 2,300 pages were submitted on those nights without a log row. The snapshots themselves are in the Wayback Machine and can be found by URL whenever a product is checked; only our own list of them is missing. Rebuilding it would take thousands of lookups and would then add rows to `data/archive/` after the fact. Not worth it; removed from the queue. The gap is recorded here so the low counts of those days are not misread.
- **2026-11-24: tests for which pages are due each day** (`dbe9219`). Five tests for `archive.todays_targets`: only on-sale products in today's third, every page due one day in three, products not seen for two days skipped, longest discounts first, and pages already handled today skipped while errors stay due. 18 tests pass. No change to behaviour.
- **2026-11-23: the archive log sync merges instead of overwriting** (`d625126`). A queued archive run checks out the commit it was scheduled on, which is older than main by the time it starts. It seeded its log from that old copy, copied it over the repo's file and rebased, which conflicted with the rows the previous run had pushed. The checkout then stayed stuck mid-rebase and every later sync of that run failed. `tracker/sync_archive_log.sh` now resets the runner's checkout to the latest main, appends only the rows main does not have (`archive.merge_logs`, two new tests), and aborts any half-finished rebase. Existing rows are never rewritten.
- **2026-11-23: the archive workflow checks out the latest main** (`d2e6ad7`, `ref: main` on the checkout step). Without it a queued run did not know which pages the previous run had already saved that day and could submit them again. No change to schedules or to what is archived.
